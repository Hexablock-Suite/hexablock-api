# adapters/http

Nest controllers, request/response DTOs, `HttpErrorFilter` and `JwtAuthGuard` that translate HTTP to use cases. `JwtAuthGuard` calls the `AuthenticateToken` input port, never the `TokenIssuer` port. `AuthDtoMapper` checks the shape of a sign-up or sign-in body, builds the `RegisterUserRequest` or the `LoginRequest` with their domain values, writes the rule messages and builds the token and user answers, so `AuthController` holds no translation code. A sign-in username that breaks its rule gets the 401 of a wrong password from the mapper. `ProgressDtoMapper` translates between the progress DTOs and `PlayerProgress`, so `ProgressController` holds no translation code. `LevelDtoMapper` does the same for `LevelsController`: it builds the `UpdateLevelsRequest` from `LevelsDto`, keeps each section as it arrives, gives each `LevelDefinition` as a `LevelDto` of `docs/level-format.md`, and writes one error detail per level problem. `LeaderboardDtoMapper` builds the query of `GetLeaderboard` from the path and turns its `Leaderboard` into the leaderboard DTOs, so `LeaderboardController` holds no translation code. `progress-values.ts` builds the progress values of a body or a path, and it writes the 400 message of the code that a factory gives (decision 11), for `ProgressDtoMapper`, `LevelDtoMapper` and `LeaderboardDtoMapper`. An adapter is the border that receives the value of a value object: `../received.ts` holds the helpers `receiveValueOf()`, `receiveKeyOf()`, `receiveBoundsOf()` and `receiveBoundValuesOf()`, which run one delivery and give what the receiver got. `CredentialsDto` and `AuthDtoMapper` receive the numbers of the credential limits through `receiveBoundValuesOf()`. `CredentialsDto` writes the OpenAPI pattern of a username, and `Username.create()` checks the same rule in the domain (decision 17 of `docs/architecture/classes.md`). Imports `src/application` and `src/domain`; never `src/infrastructure`.
