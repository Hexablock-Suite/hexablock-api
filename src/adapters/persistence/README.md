# adapters/persistence

Repository adapters that implement application ports with Drizzle ORM. Imports `src/application`, `src/domain` and `drizzle-orm`, the one package it may import (rule `persistence-adapters-import-only-drizzle`); never `src/infrastructure`, never `@nestjs/*` and never `src/adapters/http` (rule `persistence-adapters-never-import-http`). The infrastructure binds each adapter to Nest and to the `DATABASE` provider in `src/infrastructure/database`. The row mappers and the repositories receive the value of a value object through the helpers of `../received.ts`, for a row field, an SQL filter or the lock key. `DrizzleProgressRepository` builds its lock key and its SQL filters from the `userId` and the `gameId` that `receiveProgressKeyOf()` receives from a `ProgressKey`. `LevelRowMapper` restores each `levels` row through `LevelValidators`, so the strategy of the row's `gameId` builds the section. A row that no strategy accepts is a broken row with its reason code and its stored version, not a server fault (#147). `receiveJsonOf()` writes the section as the JSON of `docs/level-format.md`. `DrizzleLeaderboardReader` reads the `progress` and `level_results` tables and joins the `users` table for the `username` of each row, the one column of the user module that it reads (#230): it filters and sums, and adds no order. `ProgressRowMapper` and `DrizzleLeaderboardReader` build each level result through `buildLevelResult()` of `../built.ts`, and `ProgressRowMapper` builds the `SyncInstant` of `updated_at` from its milliseconds. A factory that gives a failed `Result` for a stored value is a server fault: `storedValue()` in `stored-value.ts` throws, and `UserRowMapper` throws for a users row (decision 11).

`schema.ts` is the Drizzle schema. It lives here because the repositories query its tables and cannot import `src/infrastructure`. `drizzle-kit` reads it to write the migrations in `drizzle/`, and `src/infrastructure/database/connection.ts` passes it to Drizzle.
