# application

Use cases and the ports they use. `ports/` holds the output ports that the outer layers implement, such as `ports/clock.ts`, which `SystemClock` in `src/adapters/clock` implements, and `ports/progress-repository.ts`, which saves and finds the whole `PlayerProgress` aggregate by its `ProgressKey`. `ports/global-board-reader.ts` reads the rows of the two global boards of a game, and `ports/level-board-reader.ts` reads the rows of the board of one level (#218). Both give `LeaderboardEntry` values (`ports/leaderboard-entry.ts`) in no order: they only filter and sum. `LeaderboardEntry` is an alias of `BoardEntry`, the entry that `RankedBoard.of()` of `src/domain/progress/ranked-board.ts` takes, so the shape `{ userId, username, result }` has one declaration (#213). The `username` is the `Username` of the account of the player (#230). `use-case.ts` holds `UseCase<TRequest, TResponse>`, the contract that every input port binds. `aspects/` holds `UseCaseAspect`, the abstract Decorator of the use cases, `LoggingAspect`, which writes each call to the `Logger` port in `ports/logger.ts` (Q12), and `AuthorizationAspect`, which lets only an account of `LevelEditors` reach the use case that it wraps and returns `NotALevelEditor` (`levels/not-a-level-editor.ts`) for any other account (#180). `AuthorizationAspect` writes no log entry: `AppModule` puts it inside `LoggingAspect`. Only `aspects/` imports that port (rule `only-aspects-import-logger-port`, #219): an optional function of `AppModule` gives `LoggingAspect` extra entries from a success, such as `unavailableLevelEntries()` of `levels/`, one entry per broken level row. `progress/` holds `SyncProgress` and `GetProgress`, which join the `UserId` and the `GameId` of their request in a `ProgressKey`, `levels/` holds `GetLevels` and `UpdateLevels` with its failures `InvalidLevels` and `NotALevelEditor` and `ListedLevels` with `UnavailableLevel` (`levels/listed-levels.ts`), the response of `GetLevels`, `leaderboard/` holds `GetGlobalLeaderboard`, which never fails, and `GetLevelLeaderboard`, which fails with `UnknownLevel` for a level that the definitions do not hold; each ranks the entries of its reader port with the comparisons of the domain, and `auth/` holds the account use cases with `SessionToken` (`auth/session-token.ts`), the response of `Login` and the request of `AuthenticateToken`. A request or response type of an input port lives next to its use case, not in `ports/`, and a port that also uses it imports it from there, so no file of `src/adapters/http` imports `ports/` (#213). Their requests, `RegisterUserRequest` and `LoginRequest` in `auth/credentials.ts`, carry a `Username` with a `Password` or a `PasswordAttempt`, which `AuthDtoMapper` of `src/adapters/http` builds, so no use case builds a domain value from a request field. A use case reads the instant from the `Clock` port as a `SyncInstant` and passes it to the domain. A use case never receives the value of a domain object: the ports carry domain types, for example `PasswordHasher` takes a `Password`, returns a `PasswordHash` and checks a `PasswordAttempt`, and no file here calls a delivery operation (`deliverTo`, `deliverKeyTo`, `deliverBoundsTo`). Imports only `src/domain`; no `@nestjs/*`, no adapters, no infrastructure.
