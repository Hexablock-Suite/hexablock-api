# application

Use cases and the ports they use. `ports/` holds the output ports that the outer layers implement, such as `ports/clock.ts`, which `SystemClock` in `src/infrastructure` implements, and `ports/progress-repository.ts`, which saves and finds the whole `PlayerProgress` aggregate by its `ProgressKey`. `ports/leaderboard-reader.ts` reads the rows of the leaderboards and gives `LeaderboardEntry` values (`ports/leaderboard-entry.ts`) in no order: it only filters and sums. `use-case.ts` holds `UseCase<TRequest, TResponse>`, the contract that every input port binds. `aspects/` holds `UseCaseAspect`, the abstract Decorator of the use cases, and `LoggingAspect`, which writes each call to the `Logger` port in `ports/logger.ts` (Q12). `progress/` holds `SyncProgress` and `GetProgress`, which join the `UserId` and the `GameId` of their request in a `ProgressKey`, `levels/` holds `GetLevels` and `UpdateLevels` with their failure `InvalidLevels`, `leaderboard/` holds `GetLeaderboard`, which orders and ranks the entries of `LeaderboardReader` with the comparisons of the domain, and `auth/` holds the account use cases. A use case reads the instant from the `Clock` port as a `SyncInstant` and passes it to the domain. A use case never receives the value of a domain object: the ports carry domain types, for example `PasswordHasher` takes a `Password`, returns a `PasswordHash` and checks a `PasswordAttempt`, and no file here calls a delivery operation (`deliverTo`, `deliverKeyTo`, `deliverBoundsTo`). Imports only `src/domain`; no `@nestjs/*`, no adapters, no infrastructure.
