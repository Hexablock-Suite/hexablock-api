# domain

Entities, value objects and domain services. Imports only other files in `src/domain`; no framework, ORM, driver or system clock. The ports live in `src/application`, so domain code never imports them: it takes the current instant as a parameter. One interface here has its implementation outside the domain: `PasswordVerifier`, which the `PasswordHasher` port extends (decision 16 of `docs/architecture/classes.md`).

`progress/` holds the `PlayerProgress` aggregate root, one per `userId` and `gameId` (API-FR-02), with its value objects `UserId`, `GameId`, `Score`, `SyncInstant` and `LevelResult`. `SyncInstant` is the instant of a sync: `PlayerProgress` keeps the instant of its last sync as `updatedAt`, and no type of the domain holds a `Date`. `PlayerProgress` delivers its parts to a `PlayerProgressReceiver` of the border with `deliverTo()`, and `PlayerProgress.restore()` builds a stored one again from those parts. A `LevelResult` holds a `LevelId`, a `Stars`, a `Moves` and an `ElapsedTime` value object in private fields: `LevelResult.of()` takes the four built, and `deliverTo()` gives them to a `LevelResultReceiver` of the border. `Standing` holds the totals of a player in one game: a `Stars`, a `LevelsCompleted`, a `Moves` and an `ElapsedTime`. Each order of a leaderboard lives in a value object: `LevelResult.isBetterThan()`, `Score.isHigherThan()` and `Standing.isBetterThan()`. The factory of each value object returns a `Result`: a raw value that breaks the rule gives a failed `Result` with the code of the rule, never an exception (decision 11). Only a guard against a defect of the caller throws, such as a missing argument of `PlayerProgress` or an instant that is not a `SyncInstant` (a `TypeError`).

`level/` holds the `LevelDefinition<TSection>` aggregate root, one per `gameId` and `levelId` (API-FR-04, DS-6), with the values of its common part (`LevelOrder`, `LevelVersion`, `TopologyId`) and the `Coordinate` of a cell. `level/fit/` and `level/sort/` hold the `FitSection` and `SortSection` value objects and their parts. Each section reads the section as it arrives, checks its own shape and returns a `Result` with a `LevelProblem` code, so a level is born valid. The `LevelValidators` domain service finds the `LevelValidator` strategy of a `gameId` with `GameId.equals()` and builds the level. `FitLevelValidator` finds the `Topology` of the level in `Topologies` with `TopologyId.equals()`, and `FitSection` checks A5 on it: `HexTopology` says which coordinates are hex cells and how a rotation step turns them. `LevelDefinition.accepts()` holds the version rule of S3-10: the stored copy rejects a lower `version` with `older-version`. The level and the composite values of its sections deliver a record of their parts to a receiver of the border, and each part delivers its own value. `docs/level-format.md` gives the shared level format.

`user/` holds the `User` aggregate root, its value objects, its `UserReceiver` and the `PasswordVerifier` interface. `User` has no public field and no public constructor: `User.register()` creates a user, `User.restore()` builds a stored one again from its value objects, `deliverTo()` gives those value objects to a `UserReceiver` of the border, and `passwordMatches()` passes its hash to a `PasswordVerifier`. `Username` and `Password` check their length with the `USERNAME_LENGTH` and `PASSWORD_LENGTH` ranges, two `Range<CharacterCount>` values that also deliver their bounds to the HTTP adapters. `CharacterCount` is the number of characters of a text: it counts code points, so an emoji is one character, and `Username`, `Password` and `PasswordAttempt` count only through it (#99). The OpenAPI pattern of a username lives in the HTTP adapter, so `user/` exports no primitive. `PasswordAttempt` is the text that a player types at sign-in: it has no length rule, so `PasswordAttempt.of()` cannot fail, and `isLongerThanAnyPassword()` tells if the text is longer than any password. `passwordMatches()` and `PasswordVerifier.verify()` take it, so no public signature of `user/` takes the typed password as a `string` (#98). `shared/` holds `Result<T, E>`, the generic `Range<T>`, the `Ordered<T>` interface of a value that orders itself, and the receiver interfaces `ValueReceiver<T>` and `BoundsReceiver<T>`. `Range<T extends Ordered<T>>` asks its values `isAfter()` and `equals()`, so no number order crosses it (decision 17 of `docs/architecture/classes.md`).

## The primitive rule and its exceptions

No primitive crosses a public signature of the domain model: an operation takes and returns domain types (design decision of 2026-11-09). A factory method is the entry: it takes the plain value of a row or a body, guards the rule and returns a `Result` with the value object or the code of the broken rule. The rule has two exceptions.

- **The boolean.** An operation that answers a question returns `true` or `false`, for example `equals()`, `Range.contains()`, `Ordered.isAfter()` and `Score.isHigherThan()`.
- **The delivery to a receiver.** A value object keeps its datum private. `deliverTo(receiver: ValueReceiver<T>): void` passes the datum to `receiver.receive(value)`, `Username.deliverKeyTo()` passes its key, and `Range.deliverBoundsTo(receiver: BoundsReceiver<T>)` passes both bounds. An aggregate delivers its parts the same way: `PlayerProgress.deliverTo()` and `User.deliverTo()` pass their value objects to a receiver in one call (decisions 2 and 16). Reason: a row, a JSON body, an SQL filter and a token keep text and numbers, so the datum must leave the domain at the border. An operation that returns the datum does what a getter does, and the professor's rule of 2026-11-09 forbids getters. So the object delivers the datum and no operation returns it (decision 15 of `docs/architecture/classes.md`). Only `src/adapters` and `src/infrastructure` receive a value. Code in `src/domain` and `src/application` never calls a delivery operation: the domain compares with `equals()` or a business operation such as `Range.isExceededBy()`, and a use case passes the object on. Gate: the lint rule `hexablock/no-delivery-call` and `test/gates/delivery.gate.spec.ts`.

The gate `test/gates/domain-surface.gate.spec.ts` (rule R-domain-surface in `AGENTS.md`) checks the primitive rule in every `.ts` file of `src/domain`. It also checks that each field is private and that no type has a getter. It accepts both exceptions and the factory of a value object that takes the raw value. Its baseline `test/gates/domain-surface.baseline.ts` lists the sites that break the rule today, one entry per site. A change removes the entries of the sites that it fixes and never adds one.
