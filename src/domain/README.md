# domain

Entities, value objects and domain services. Imports only other files in `src/domain`; no framework, ORM, driver or system clock. The ports live in `src/application`, so domain code never imports them: it takes the current instant as a parameter. One interface here has its implementation outside the domain: `PasswordVerifier`, which the `PasswordHasher` port extends (decision 16 of `docs/architecture/classes.md`).

`progress/` holds the `PlayerProgress` aggregate root, one per `userId` and `gameId` (API-FR-02), with its value objects `UserId`, `GameId`, `Score` and `LevelResult`. A `LevelResult` holds a `LevelId`, a `Stars`, a `Moves` and an `ElapsedTime` value object. `Standing` holds the totals of a player in one game: a `Stars`, a `LevelsCompleted`, a `Moves` and an `ElapsedTime`. Each order of a leaderboard lives in a value object: `LevelResult.isBetterThan()`, `Score.isHigherThan()` and `Standing.isBetterThan()`. A broken rule of the older value objects throws `ProgressError`. The factories of `LevelsCompleted` and `Standing` return a failed `Result` with the code of the rule (decision 11).

`level/` holds the `LevelDefinition<TSection>` aggregate root, one per `gameId` and `levelId` (API-FR-04, DS-6), with the values of its common part (`LevelOrder`, `LevelVersion`, `TopologyId`) and the `Coordinate` of a cell. `level/fit/` and `level/sort/` hold the `FitSection` and `SortSection` value objects and their parts. Each section reads the section as it arrives, checks its own shape and returns a `Result` with a `LevelProblem` code, so a level is born valid. The `LevelValidators` domain service finds the `LevelValidator` strategy of a `gameId` with `GameId.equals()` and builds the level. `FitLevelValidator` finds the `Topology` of the level in `Topologies` with `TopologyId.equals()`, and `FitSection` checks A5 on it: `HexTopology` says which coordinates are hex cells and how a rotation step turns them. `LevelDefinition.accepts()` holds the version rule of S3-10: the stored copy rejects a lower `version` with `older-version`. The level and the composite values of its sections deliver a record of their parts to a receiver of the border, and each part delivers its own value. `docs/level-format.md` gives the shared level format.

`user/` holds the `User` aggregate root, its value objects, its `UserState` snapshot and the `PasswordVerifier` interface. `User` has no public field and no public constructor: `User.register()` creates a user, `User.restore()` builds a stored one again, `snapshot()` gives a copy of its state, and `passwordMatches()` passes its hash to a `PasswordVerifier`. `Username` and `Password` check their length with the `USERNAME_LENGTH` and `PASSWORD_LENGTH` ranges, which also deliver their bounds to the HTTP adapters. `shared/` holds `Result<T, E>`, the generic `Range<T>` and the receiver interfaces `ValueReceiver<T>` and `BoundsReceiver<T>`.

## The primitive rule and its exceptions

No primitive crosses a public signature of the domain model: an operation takes and returns domain types (design decision of 2026-11-09). A factory method is the entry: it takes the plain value of a row or a body and guards the rule. The rule has two exceptions.

- **The boolean.** An operation that answers a question returns `true` or `false`, for example `equals()`, `Range.contains()` and `Score.isHigherThan()`.
- **The delivery to a receiver.** A value object keeps its datum private. `deliverTo(receiver: ValueReceiver<T>): void` passes the datum to `receiver.receive(value)`, `Username.deliverKeyTo()` passes its key, and `Range.deliverBoundsTo(receiver: BoundsReceiver<T>)` passes both bounds. Reason: a row, a JSON body, an SQL filter and a token keep text and numbers, so the datum must leave the domain at the border. An operation that returns the datum does what a getter does, and the professor's rule of 2026-11-09 forbids getters. So the object delivers the datum and no operation returns it (decision 15 of `docs/architecture/classes.md`). Only `src/adapters` and `src/infrastructure` receive a value. Code in `src/domain` and `src/application` never calls a delivery operation: the domain compares with `equals()` or a business operation such as `Range.isExceededBy()`, and a use case passes the object on. Gate: the lint rule `hexablock/no-delivery-call` and `test/gates/delivery.gate.spec.ts`.

The gate `test/gates/domain-surface.gate.spec.ts` (rule R-domain-surface in `AGENTS.md`) checks the primitive rule in every `.ts` file of `src/domain`. It also checks that each field is private and that no type has a getter. It accepts both exceptions and the factory of a value object that takes the raw value. Its baseline `test/gates/domain-surface.baseline.ts` lists the sites that break the rule today, one entry per site. A change removes the entries of the sites that it fixes and never adds one.
