# AGENTS.md

Rules for every contributor, human or agent, in this repository. Each rule names the gate that enforces it, or says "no gate". Run `pnpm verify` before you push; CI runs the same command in the `verify` job.

## Commands

- `pnpm verify`: lint, format:check, typecheck, test, arch, openapi:check, in that order.
- `pnpm test`: unit, integration and gate tests, then e2e tests. It runs both suites, the behavior suite and the gate suite.
- `pnpm test:behavior`: the behavior suite, the tests that run the code: unit, integration and e2e tests. It holds 1,302 tests on 2026-11-28.
- `pnpm test:gates`: the gate suite, the tests that read the code, the documents or the configuration to hold a rule. It holds 118 tests on 2026-11-28. `vitest.gates.config.ts` lists the gate files.
- `pnpm test:fast`: the fast feedback command (#256), the 881 tests of `test/unit/` and `test/domain/`. They start no database and no HTTP application. It skips the integration tests, the e2e tests and the gates outside `test/domain/`; `pnpm verify` runs them. It took 6.3 s and 5.6 s, measured on 2026-11-28, Node v26.13.1, load 16.0 and 16.1. `pnpm test:unit` is not the fast command: it took 31.4 s and 33.2 s (load 12.7 and 13.3).
- `pnpm arch`: dependency-cruiser layer rules.
- `pnpm contract:verify`: verify the client pact against the API at `BACKEND_URL`. `PACT_FILE` picks a local pact. The API must be the provider composition: `node --env-file=.env.example scripts/contract/start-provider.js` starts it with the state-change endpoint of the pact provider states (#151).
- `pnpm db:generate`: write a migration into `drizzle/` from the schema. `pnpm db:migrate` applies them to `DATABASE_URL`.
- `pnpm openapi:export`: build the app and write `openapi/openapi.json`. `pnpm openapi:check` fails when that file is stale.

## Rules

- Read `docs/REQUIREMENTS.md` before you change behavior. When a requirement, assumption or professor answer changes, update it here and in the app repo's canonical file. Gate: no gate. <!-- rule: R-requirements -->
- Write every artifact, comment and commit message in English. Gate: no gate. <!-- rule: R-english -->
- Write commit messages as Conventional Commits. Gate: `commitlint.config.cjs`, `.vite-hooks/commit-msg`, `test/gates/commit-message.gate.spec.ts`. <!-- rule: R-conventional-commits -->
- Name each test `should_<expected_result>_when_<condition>`. Gate: `vite.config.ts`, `test/gates/test-name.gate.spec.ts`. <!-- rule: R-test-names -->
- Put each gate test in `test/gates/`. A gate test reads the code, the documents or the configuration to hold a rule; a behavior test runs the code. A gate that lives with behavior tests stays in its folder and goes into `GATE_FILES` of `vitest.gates.config.ts`, as `test/integration/in-memory-database.spec.ts`, `test/domain/level/level-problem.spec.ts` and the OpenAPI drift test of `test/health.e2e-spec.ts` do (#253). Each test file of `pnpm test` belongs to one suite; only `test/health.e2e-spec.ts` has a test in each. Gate: `vitest.gates.config.ts`, `test/gates/test-suites.gate.spec.ts`. <!-- rule: R-test-suites -->
- Keep `src/domain` free of imports from outside `src/domain`. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-domain-pure -->
- Keep `src/domain` free of import cycles: no file of `src/domain` reaches itself through its imports, and a type-only import counts. A file directly in a folder of `src/domain`, such as `src/domain/level/`, never imports a subfolder of that folder, such as `level/fit/`: a type that the shared part and a variant both use lives in the shared folder, as `Rotation` lives in `src/domain/level/` next to `Coordinate` (#221). Two types that need each other share one file, as `StoredLevel` and `LevelDefinition` do. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-domain-no-cycles -->
- Let `src/application` import only `src/domain`; build aspects as custom decorators, not Nest interceptors. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-application-pure -->
- Write to the `Logger` port only from `src/application/aspects`: no use case and no other file of `src/application` imports `src/application/ports/logger.ts`. A use case that needs an extra log entry gets it from `LoggingAspect`, through a function of its success value that `AppModule` gives the aspect, as `GetLevels` does with `unavailableLevelEntries()` (#219). Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-logger-in-aspects -->
- Keep `@nestjs/*` out of `src/adapters/persistence`; `drizzle-orm` is allowed there. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-persistence-no-nest -->
- Never import `src/infrastructure` from `src/adapters`. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-adapters-no-infrastructure -->
- Never import `src/adapters/persistence` from `src/adapters/http`, and never import `src/adapters/http` from `src/adapters/persistence`; a controller talks to use cases only. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-http-persistence-apart -->
- Let `src/adapters/http` import only `@nestjs/*` among packages; a Node built-in is not a package. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-http-adapters-only-nest -->
- Let `src/adapters/persistence` import only `drizzle-orm` among packages. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-persistence-adapters-only-drizzle -->
- Keep every package out of the files of `src/adapters` outside `http/`, `persistence/`, `jwt/` and `logging/`; a new folder of layer 3 gets its own rule before it imports its library. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-other-adapters-no-package -->
- Let `src/adapters/jwt` import only `@nestjs/jwt` among packages, and `src/adapters/logging` only `@nestjs/common`. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-system-adapters-one-package -->
- Let `src/adapters/crypto` import only `node:crypto` among Node built-ins, and keep every Node built-in out of `src/adapters/clock`. Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-system-adapters-built-ins -->
- Put every class that implements a port of `src/application/ports` in `src/adapters`, in the folder of the one library that it adapts; `src/infrastructure` keeps glue code only: the configuration, the database connection, `AppModule` and the implementations of interfaces that layer 3 owns. No file of `src/infrastructure` except `app.module.ts` imports `src/application/ports` (#212, option C). Gate: `.dependency-cruiser.cjs`, `test/gates/architecture.gate.spec.ts`. <!-- rule: R-ports-implemented-in-adapters -->
- Read time in `src/application` from the `Clock` port in `src/application/ports/clock.ts` and the duration of a use case call from the `Stopwatch` port in `src/application/ports/stopwatch.ts` (#181), and pass the instant to `src/domain` as a parameter; the domain never imports a port. Take randomness from an injected seeded source in both layers. The gate also bans the ambient forms `Math.random`, `Date.now`, `new Date()`/`Date()`, `crypto.randomUUID`, `crypto.getRandomValues`, `performance.now` and every read of `process.env` in `src/domain` and `src/application`. Gate: `vite.config.ts`, `scripts/lint/hexablock-plugin.js`, `test/gates/determinism.gate.spec.ts`. <!-- rule: R-deterministic-core -->
- Keep every use of a delivery operation of a value object (`deliverTo`, `deliverKeyTo`, `deliverBoundsTo`: a call, a reference or a destructuring) out of `src/domain` and `src/application`; only `src/adapters` and `src/infrastructure` receive the value of a domain object. A delivery operation is not a getter: it returns nothing and pushes the value to the border (design decision of 2026-11-15). Gate: `vite.config.ts`, `scripts/lint/hexablock-plugin.js`, `test/gates/delivery.gate.spec.ts`. <!-- rule: R-no-delivery-call -->
- Await no port call in each pass of a loop in `src/application`: a use case reads all items of a request in one call of a port, so its cost does not grow with the count of items (#217). A loop that must wait for each step, such as the saves of `UpdateLevelsUseCase`, disables the rule on its line and gives the reason. Gate: `vite.config.ts`, `test/gates/await-in-loop.gate.spec.ts`. <!-- rule: R-no-await-in-loop -->
- Keep every field of a class or an interface in `src/domain` private, and declare no `get` or `set` accessor and no method whose name starts with `get`; a public read-only field counts as a getter. No `string`, `number` or `Date` crosses a public signature of `src/domain`: a parameter, a return type, an exported constant or an exported type. Three cases pass: an operation that returns a boolean, the factory of a value object that takes the raw value (a static method of a class that declares a delivery operation, which returns the class or a `Result` of it and takes only raw values), and the delivery operations `deliverTo`, `deliverKeyTo` and `deliverBoundsTo` (decision 15). An aggregate root that `AGGREGATE_ROOTS` of `test/gates/domain-surface.ts` lists (`User`, `PlayerProgress`, `LevelDefinition`) declares a private constructor, and no class or interface of `src/domain` declares a `snapshot()` method (#255); a new root joins that list. `test/gates/domain-surface.baseline.ts` lists the sites that break the rule today, one entry per site: a change removes the entries of the sites that it fixes and never adds one. Gate: `test/gates/domain-surface.gate.spec.ts`. <!-- rule: R-domain-surface -->
- Follow the section «Domain design rules» of `docs/architecture/classes.md` when you add or change a class in `src/domain` or a class view: aggregates, domain services, value objects, time values, ranking orders and names. Rule R-domain-surface checks the private fields, the getters and the primitives in public signatures; no gate checks the other rules. Gate: `test/gates/domain-surface.gate.spec.ts` for the part that rule R-domain-surface checks, no gate for the rest. <!-- rule: R-domain-design -->
- Keep the shape of `docs/architecture/classes.md`: the decisions of «Decisions to check with the team» are numbered 1 to n with no gap and no repeat, each decision starts a line of its own, no line is longer than 6,000 code points, and no git conflict marker or «characters truncated» text stays in the file. A decision that passes the limit goes on in paragraphs indented under its number, and no paragraph starts with `<number>. `, or the formatter reads it as a new item and numbers the list again (#249). Gate: `test/gates/classes-shape.gate.spec.ts`. <!-- rule: R-classes-shape -->
- Write the comments of `src/domain` in the words of the domain: no comment names a column, a table, Postgres, SQL, Drizzle, a row mapper, a persistence adapter, a lock of the store, a stored row or a broken row (#177). The gate reads only the comments, never the code, and its words have no other meaning in the domain: a plain «row» stays allowed, because a grid and a leaderboard have rows too. A rule that exists because of a limit of the store keeps that limit at the border, and no domain comment names it. Gate: `test/gates/persistence-words.gate.spec.ts`. <!-- rule: R-domain-words -->
- Run the Node version of `.node-version`, one exact Node 26 release that the three CI jobs also read. `engines.node` of `package.json` starts at that version and stays below 27, and `engineStrict: true` in `pnpm-workspace.yaml` makes `pnpm install` and every `pnpm` script fail on an older version (#250). Gate: `test/gates/ci-contract.spec.ts`. <!-- rule: R-pinned-node -->
- Keep `pnpm verify` and the CI `verify` job in step. Gate: `.github/workflows/ci.yml`, `test/gates/ci-contract.spec.ts`. <!-- rule: R-verify-parity -->
- Run `pnpm openapi:export` after every HTTP change and commit `openapi/openapi.json`; the client generates its API types from it. Gate: `scripts/openapi/export.js`, `test/health.e2e-spec.ts`. <!-- rule: R-openapi-drift -->
- Keep every client pact interaction green against this API; a missing pact fails the job. Only the provider composition of `scripts/contract/start-provider.js` mounts the state-change endpoint, never `AppModule` (#151). Gate: the contract job in `.github/workflows/ci.yml`, `scripts/contract/verify-provider.js`, `test/gates/ci-contract.spec.ts`, `test/provider-states.e2e-spec.ts`. <!-- rule: R-contract -->
- Test repositories on in-memory PGlite through `test/support/test-database.ts`, never on a shared Postgres; change tables only through `drizzle/` migrations. Two exceptions need two real sessions to show an advisory lock, so they run only when `HB_TEST_PG_URL` points at a throwaway Postgres, as in the CI job `postgres-lock`, which runs both: `test/integration/drizzle-progress-repository.concurrency.spec.ts` and `test/integration/drizzle-level-repository.concurrency.spec.ts`. Gate: `test/integration/in-memory-database.spec.ts`, `test/gates/ci-contract.spec.ts`. <!-- rule: R-database-harness -->
- Never bypass a git hook; CI repeats every hook check. Gate: `.github/workflows/ci.yml`, `test/gates/ci-contract.spec.ts`. <!-- rule: R-no-hook-bypass -->
- Keep the README and AI_USAGE.md sections of the project statement. Gate: `test/gates/docs-skeleton.spec.ts`. <!-- rule: R-docs-skeleton -->
- Document every entry of `dependencies` and `devDependencies` of `package.json` in `docs/DEPENDENCIES.md` with a truthful reason. Gate: `test/gates/dependencies.gate.spec.ts`. <!-- rule: R-dependencies-doc -->
- Log AI help for each task in AI_USAGE.md. Gate: no gate. <!-- rule: R-ai-usage-log -->
- Merge to `main` only through a pull request with a green `verify` job. Gate: no gate. <!-- rule: R-protected-main -->
- At the end of each sprint of the plan in [hexablock-app `docs/ROADMAP.md`](https://github.com/Hexablock-Suite/hexablock-app/blob/main/docs/ROADMAP.md), tag `v0.N.0`, the same tag as the app; the final delivery is `v1.0.0`. First move the `## [Unreleased]` entries of `CHANGELOG.md` into a `## [x.y.z] - YYYY-MM-DD` section for that version. Then create the GitHub Release by hand, with that section as its notes. Gate: `test/gates/changelog.gate.spec.ts` (it pins the CHANGELOG format, not the tag or the release). <!-- rule: R-sprint-release -->
